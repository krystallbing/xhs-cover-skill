# 本地历史记录与经验读取

每次开始封面任务、继续修改旧封面或收到用户反馈时读取本文件。路径均相对于本 skill 根目录，不是调用时的任意工作目录。由执行 skill 的 AI 在工作过程中读写记录，不需要后台服务。

## 初始化和隔离

首次使用时自动创建 `private/identity/`、`private/history/`、`private/preferences.md` 和 `private/history/index.md`。已存在的文件保留，不重新初始化或覆盖。新安装得到规则和公开示例，不携带其他用户的私人记录。

先确认根 `.gitignore` 包含 `/private/`。Git 仓库中用 `git check-ignore` 检查私有路径，并用 `git ls-files private` 确认没有已跟踪的私人文件。发现已被跟踪时，报告具体路径并在发布前处理；添加忽略规则不能清除已有提交。没有 Git 的安装也可以本地保存，但不声称已经验证 Git 排除。

所有新的人物照片副本、当期素材、生成图、诊断记录和反馈都放在 `private/`。只复制本次实际使用的素材，保留源文件；不要批量扫描或收集用户的其他照片。已有默认照片路径仍可使用，新的固定人物副本存入 `private/identity/`，更新本地 `config.md` 的路径并保留其余配置。

发布时检查暂存文件，排除 `private/`、个人配置及其他位置的私人素材；不执行 `git add -f private`。打包分享时按公开文件清单打包，不压缩整个工作目录。这里的“本地私有”指不进入公开 Git 仓库；实际生图所需的参考图仍会传给用户选定的生图工具。

## 任务目录与文件

每个新主题创建一个唯一目录：`private/history/YYYYMMDD-HHMMSS-短标识/`，日期使用用户时区；碰撞时加后缀，不覆盖。目录名不放完整文章或个人姓名。修改同一任务时复用目录；不确定用户指哪次作品且上下文无法消歧时再问。

```text
private/
├── identity/
├── preferences.md
└── history/
    ├── index.md
    └── <任务ID>/
        ├── brief.md
        ├── prompts.md
        ├── review.md
        ├── feedback.md
        ├── assets/
        └── images/
```

仅为开始的真实任务创建记录，不生成虚构的成功案例。不把本次安装、脚本检查或规则修改当作封面任务。

| 文件 | 保存内容 |
|---|---|
| `brief.md` | 主题摘要、四种推荐与三个标题、用户最终选择、人物模式及来源（已保存默认／本次覆盖）、验收要求、各素材的用途与归档路径；无需复制无关聊天 |
| `prompts.md` | 按候选 A/B 和版本记录实际发送给工具的完整提示词、输入素材对应关系、工具名及已知参数；未知参数写未知，不记录密钥 |
| `review.md` | 提示词展示前实际读取的模板及相关示例、自检发现与处理；每个实际版本的图像路径、检查项与结论、可见问题、修正动作及复查结果。只记录实际执行的操作；区分观察与推测，缺少图像证据标待确认 |
| `feedback.md` | 用户明确反馈、选择的候选和版本、是否确认最终稿；未给原因就写“未说明”，未评分就写“未评分” |
| `assets/` | 本次使用的截图等素材副本，固定人物照可引用 `identity/` 中的文件，不必每次复制 |
| `images/` | 各版本成图，使用 `A-v01.png`、`A-v02.png`、`B-v01.png` 等名称，保留真实格式及旧版本，记录最终选定路径 |

原始版、自动纠错版和用户精修版都沿用同一候选的递增版本号，不覆盖；已存在文件先核实再跳过，重复继续任务时不得再次重复归档。同一任务存在其他写入时，先读最新文件，再追加本次内容。

向用户展示的图片版本标签与归档名称保持一致。每次修正的 `review.md` 记录关联修改前后版本、修改原因、实际变化及复查结论；`feedback.md` 标明用户意见针对的候选和版本，无法确定时标待确认。保留这些对比供后续经验回顾，不因展示摘要而省略历史记录，也不把 AI 自检通过当作用户认可。

## 自动留存时机

1. **任务开始**：初始化缺失目录，创建任务记录，并在索引加入“进行中”。没有素材或用户选择时记录待定，不编造。
2. **提示词确认和调用工具前**：保存最终提示词、参考图用途和确认过的验收要求。
3. **每次生成或修改后**：把工具返回的本地图片复制进该任务的 `images/`，保留原文件，然后追加查验记录。工具只能返回不可保存的媒体时，记录可用引用和“未本地归档”，遵循工具限制；不能凭空写一个成功保存路径。生成失败也记录失败，不计作已生成图片。
4. **首次交付前**：完成两张最新候选的归档与检查记录，将索引状态设为“待选择”；如有未解决问题或缺失图片，明确记录。反馈未到达不能自动标成已完成。
5. **用户反馈后**：立即追加反馈；修改时继续原任务，最终确认后将索引改为“已确认”，写明最终文件。局部修改不要求重新填写流程。

自动保存失败时报告未保存部分，保留工具原始输出，不假装历史已持久化。没有文件写入能力时仍可完成可执行的设计工作，但明确历史机制未运行。

## 索引、偏好与下次读取

`index.md` 使用下列列名，每个任务一行，更新本任务行而非反复新增：

| 任务ID | 主题 | 人物模式 | 构图 | 状态 | 最终版本 | 关键问题或反馈 | 记录目录 |
|---|---|---|---|---|---|---|---|

`preferences.md` 仅存用户明确要求跨任务沿用的偏好，记录适用范围、用户依据及来源任务ID；新偏好与旧偏好冲突时标明取代关系，不静默丢失依据。`config.md` 负责人物来源、可选参考照路径、默认人物模式、工具等配置；本次造型要求只写进任务记录，不自动改写默认模式。已有其他偏好可以继续读取，逐步迁入本文件时不要产生矛盾的两份值。

新任务开始时先读偏好和索引，按本次主题、构图、人物模式及相同问题挑最多三条相关历史，阅读其验收、检查和反馈。可参考“某种遮挡曾使文字不可读”等有证据的经验，不把用户选 A 推断成喜欢 A 的全部字体、服装和颜色。当前指令高于已确认偏好，已确认偏好高于历史推测。

AI 检查记录使用“通过／需修正／待确认”并附依据，与用户喜好分开。用户评分若存在则如实记录原量表，未提供评分不主动追加评分问卷，也不由 AI 代替用户打满意度分数。

## 积累后回顾

先积累历史，不自动改写 `SKILL.md` 或公开模板。以用户确认的最终封面计数：同一任务的两张候选和重试版本不重复计数。达到约 10 个已确认任务后可在交付时轻提示一次“可以进行经验回顾”；用户希望积累到 20 个时按其要求等待，不能因此打断生图。

用户要求回顾时，总结反复出现的问题、有效修正和明确偏好，注明来源任务与反例；建议先保存在 `private/`。个人审美只更新已确认的私人偏好，通用规则的修改需用户授权。历史多不等于已训练模型，不声称会自动改变生图模型参数或保证以后不再失败。
